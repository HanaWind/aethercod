# Aethercod

> **早期开发阶段（Early Development）**：功能仍在持续迭代完善中。如有问题、建议或改进，欢迎提交 Issue / PR。

Aethercod 是一个本地优先的奇幻世界观资料库。它使用词条、时间和双向关系组织人物、地点、政权、事件、物品等设定，并将一个资料库完整保存在单个 `.aethercod` 文件中。

桌面界面使用 **pywebview + React + TypeScript + Tailwind CSS + Framer Motion**，通过 pywebview `js_api` 直接调用 Python 桥接层。生产运行加载本地静态文件，不启动 HTTP 服务；领域模型、SQLite 数据库和既有 Python 服务保持不变。资料默认只保存在本机。

## 主要功能

### 资料库

- 新建资料库时可设置资料库名称、纪年法名称、作者和说明。
- 打开、关闭和备份 `.aethercod` 项目，也兼容旧的 `.db`、`.sqlite` 和 `.sqlite3` 文件。
- 在“资料库设置”中随时修改项目元数据。
- 完整资料库可导出为 JSON，也可按 UUID 合并导入另一份资料。
- 只读文件会自动进入只读状态，搜索、浏览、时间线、关系图和导出仍可使用。

### 类型化词条

每个词条都有名称、摘要、别名、标签、颜色、正文、备注、日期和 UUID。当前内置九类词条：

| 类型 | 专用属性示例 |
| --- | --- |
| 人物 | 中文名、英文名、称号、性别/代词、种族 |
| 国家/政权 | 正式名称、制度、面积、人口、地理、文化与经济 |
| 地区/地点 | 地点类别、地位、面积、人口、地理、地区特色 |
| 机构/组织 | 宗旨、职能 |
| 部分/分支 | 职能、规模 |
| 事件 | 前因、经过、结果 |
| 物品 | 类别、材料、能力、历史 |
| 种族 | 寿命、生理特征、文化特征 |
| 概念/魔法 | 体系/流派、规则、代价 |

所有内置类型还共享“定位/身份”和“核心特征”，便于表达混合身份和不同世界观中的特殊角色。当前类型可继续添加自己的属性定义，支持：

- 短文本和多行文本
- 整数和数字
- 布尔值和枚举选择
- 纪年日期
- JSON
- 单个词条引用和词条引用列表

词条列表可按类型筛选，并可搜索名称、摘要、正文、别名、别名重定向和属性值。界面显示带连字符的标准 UUID，数据层同时兼容历史项目中的 32 位小写形式。

### 关联与跳转

- 关系由源词条、目标词条、正向名称、反向名称和说明组成。
- 同一关系会从两端显示，并按照当前词条视角选择正向或反向名称。
- 词条编辑页可新增、修改和删除关系，关联列表可直接预览目标词条。
- 预览弹窗可跳转到完整词条；时间线和关系图也使用同一套词条预览与跳转逻辑。
- 正文支持 `[[UUID]]` 和 `[[UUID|显示文本]]` 形式的内部引用，数据校验会报告不存在或已删除的引用。

### 可视化时间线

- 使用当前资料库的自定义纪年法，例如“泰拉纪元”。
- 年份支持直接输入正数、零和负数；负数显示为“纪元前 N 年”。
- 支持年份、年月、完整日期和时间范围。
- 鼠标位于时间线内时，可围绕指针位置滚轮缩放；工具栏也提供放大、缩小和适配全部内容。
- 同期事件会自动错层，单击查看事件详情，详情中可跳转到对应词条。
- 可按词条类型筛选时间线内容。

### 交互关系网

- 可在“完整关系网”和“当前词条的直接关联”之间切换。
- 椭圆节点会保持轻微漂浮，可拖动调整位置，也可缩放和一键适配视图。
- 双击节点打开词条预览，预览中可继续跳转到词条编辑页。
- PNG 导出会根据当前节点和连线的实际覆盖范围计算画布，不依赖窗口可见区域。

### 数据校验

“数据校验”页面会扫描并定位以下问题：

- 非法 UUID
- 不存在或已经删除的关系端点
- 不存在或已经删除的正文引用
- 重复别名及异常别名重定向
- 缺少必填属性或属性值类型错误
- 无效日期和日期范围
- 重复关系

### 界面体验

- 默认浅色的三栏工作台，支持记忆深浅主题、分类独立折叠、动态主题色、关联跳转和反向引用。
- 从左侧打开资料库设置、全库时间线和关系图谱。设置页可修改资料库信息、管理词条类型和自定义字段。
- 标题栏可开启只读模式。浏览、搜索和跳转仍可使用，桥接层会拒绝项目写入。
- 标题、摘要和 Markdown 正文采用阅读与编辑切换，按资料库中选定的手动、定时或实时策略保存到 SQLite。
- 类型自定义属性以网格方式展示，纪年节点呈现在词条时间线上。
- `Ctrl+K` / `Cmd+K` 打开键盘可操作的全局搜索面板。
- 关系图谱支持词条筛选、关联子网查看、节点拖动和单击居中。
- 保存机制可设置为手动保存、分钟间隔自动保存或实时自动保存。手动模式使用工具栏保存按钮或 `Ctrl+S`。
- 时间线事件可记录详细说明，并在时间线视图中打开详情弹窗。
- QML 和 QWidget 界面仍保留，可通过环境变量启动。

## 快速开始

### 环境要求

- Python 3.11 或更高版本
- pywebview 5.3 或更高版本
- Node.js 20.19 或更高版本及 npm，用于构建前端静态资源
- PySide6 6.7 或更高版本，仅用于运行兼容 Qt 界面和对应测试

Windows PowerShell 示例：

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
cd frontend
npm install
npm run build
cd ..
```

启动桌面应用：

```powershell
python -m aethercod
```

只运行桌面前端时可安装 `aethercod` 本体依赖。`.[dev]` 会额外安装 Qt，用于测试和开发旧界面；只需兼容界面时可安装 `.[legacy-ui]`。

安装后也可以使用：

```powershell
aethercod
# 或不显示控制台的 GUI 入口
aethercod-gui
```

首次使用时选择“创建资料库”，填写项目参数并选择保存位置。随后可以创建词条、编辑类型属性、添加日期和关系，再通过分类列表与搜索面板浏览设定。

生产界面加载 `src/aethercod/frontend_dist/` 中的本地文件。开发界面可启动 Vite，然后在另一个终端中设置开发地址：

```powershell
cd frontend
npm run dev
```

```powershell
$env:AETHERCOD_DEV_URL = "http://127.0.0.1:5173"
python -m aethercod
```

### 兼容界面

旧 QML 与 QWidget 界面仍保留用于兼容和辅助迁移：

```powershell
$env:AETHERCOD_UI = "widgets"
python -m aethercod
# 或使用旧 QML 工作台
$env:AETHERCOD_UI = "qml"
python -m aethercod
```

## `.aethercod` 文件

`.aethercod` 是 SQLite 数据库文件，不是压缩包。当前 schema 版本为 v3，默认启用外键检查和 WAL：

- 打开 v1 项目时会自动迁移别名重定向、属性元数据和日期范围字段。
- 打开 v2 项目时会自动为时间线事件增加说明字段，既有事件说明默认为空。
- 高于当前版本的 schema 会被拒绝打开，避免旧程序修改未知格式。
- 迁移和 JSON 导入均使用事务；失败时会回滚本次操作。
- 应用内“备份资料库”使用 SQLite backup API，可包含仍在 WAL 中的数据。

程序运行时不建议只复制主数据库文件作为备份；请优先使用应用内备份功能。

## 数据模型

| 对象 | 用途 |
| --- | --- |
| `Entity` | 词条主体，保存名称、类型、正文、颜色、时间戳等通用信息 |
| `EntityType` | 人物、地点、事件等词条类型 |
| `FieldDefinition` | 类型专属属性的名称、数据类型、说明、选项和必填规则 |
| `Relation` | 两个词条之间带正反向名称的关系 |
| `TimelineDate` | 词条的年份、日期或时间范围 |
| Alias / Tag | 词条的别名解析和分类标签 |

实体、关系、属性定义和日期均使用 UUID。显示时采用 RFC 4122 形式，例如：

```text
123e4567-e89b-12d3-a456-426614174000
```

内部引用可以写在正文中：

```markdown
[[123e4567-e89b-12d3-a456-426614174000|王都]]
```

## 纪年与日期规则

年份是带符号整数。以“泰拉纪元”为例：

| 输入 | 显示 |
| --- | --- |
| `-120` | 泰拉纪元前 120 年 |
| `0` | 泰拉纪元 0 年 |
| `347` | 泰拉纪元 347 年 |
| `347-05` | 泰拉纪元 347 年 5 月 |
| `347-05-18` | 泰拉纪元 347 年 5 月 18 日 |

时间范围还可以设置独立的结束年份或结束日期。日期编辑器会检查日期中的年份与年份输入是否一致。

## 导入、导出与备份

- **导出资料库 JSON**：导出项目参数、类型、属性定义、词条、别名、标签、日期和关系。
- **导入并合并 JSON**：按 UUID 合并；写入前先规范化和校验全部数据，任一错误都会回滚。
- **备份资料库**：生成可独立打开的 `.aethercod` 副本。
- **导出关系图 PNG**：以当前关系图内容边界生成图片。

批量导入或大规模修改前，建议先创建资料库备份。

## 项目结构

```text
src/aethercod/
├── __main__.py             # 命令行和 GUI 启动入口
├── db.py                   # SQLite schema、内置类型和迁移
├── models.py               # 领域对象、UUID 与日期校验
├── repositories.py         # 词条、关系、属性和分类仓储
├── services.py             # 搜索、时间线和完整性校验
├── exchange.py             # JSON、Markdown 与数据库备份
├── resources/              # SVG、PNG 和 ICO 应用资源
└── ui/
    ├── webview_app.py      # pywebview 桌面窗口
    ├── bridge_api.py       # pywebview js_api 与领域服务适配层
    ├── qml_app.py          # Qt Quick 应用初始化
    ├── qml_backend.py      # 兼容 QML 的数据层适配
    ├── qml/Main.qml        # 兼容 QML 工作台
    ├── main_window.py      # 兼容 QWidget 界面
    ├── graph_view.py       # 兼容界面的关系图
    └── timeline_view.py    # 兼容界面的时间线

tests/                      # 数据层、交换层和 Qt 界面测试
frontend/                   # Vite、React、TypeScript 与 Tailwind CSS 工程
```

React 前端只通过 `BridgeAPI` 暴露的 pywebview `js_api` 调用数据层。SQLite schema、仓储和服务层不依赖具体界面。

## 开发与测试

安装开发依赖：

```powershell
python -m pip install -e ".[dev]"
```

运行测试和静态检查：

```powershell

python -m compileall -q src tests
```

```powershell

```

## 当前限制

- React 工作台尚未迁移数据校验、JSON 导入导出和备份界面，这些功能仍可从旧 QML 或 QWidget 界面使用。
- 删除词条使用软删除保留数据，React 工作台尚未提供回收站管理页面。
- 拖动后的关系图布局只在当前会话中生效，尚未写入项目文件。
- 应用面向单机资料库，没有多人实时同步和权限系统。
